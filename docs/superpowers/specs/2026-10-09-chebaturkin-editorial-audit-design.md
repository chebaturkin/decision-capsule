# Decision Capsule — редакторский и интерфейсный аудит

## Цель

сделать продукт цельным по голосу и терминологии: пользователь должен сразу понимать, что хранит здесь решение, когда к нему вернуться и что произойдёт с данными.

## Границы

- интерфейс, ошибки, пустые состояния, подсказки, диалоги, доступные названия и метаданные страницы;
- README и описание публикации через GitHub Pages;
- небольшие защитные правки, которые не меняют формат данных и пользовательский сценарий;
- без аккаунтов, сервера, внешних шрифтов, аналитики и новых необратимых действий.

## Редакторские решения

- одна сущность называется «капсула»;
- «архив» — это коллекция капсул и JSON/Markdown-выгрузка;
- «итог» — запись о том, что произошло после открытия;
- фразы и заголовки в русском интерфейсе начинаются со строчной буквы;
- имена `Decision Capsule`, `IndexedDB`, `JSON`, `Markdown`, `GitHub Pages`, URL, ключи данных и код сохраняют нормативный регистр;
- обращение к пользователю — «вы»; кнопка называет действие, ошибка объясняет следующий шаг;
- обещания и оценки остаются только там, где их подтверждает работа продукта.

## Визуальные решения

сохраняются пергаментная основа, бордо, латунь, тёмно-зелёный и уголь, а также serif для вопросов и mono для дат и статусов. интерфейс остаётся плоским и библиотечным: линии, конверт, номер капсулы и печать. увеличиваются читаемость вторичного текста, понятность фокуса и перенос длинных ссылок; градиенты, pill-формы и стеклянные поверхности не добавляются.

## Проверяемые результаты

1. все видимые пользовательские строки в `app.js`, `index.html` и экспортируемом Markdown используют согласованные термины и регистр;
2. README описывает те же ограничения: локальное хранение, дату устройства и отсутствие шифрования в hash-ссылке;
3. диалоги сохраняют фокус, закрываются через Escape и возвращают фокус на вызвавшую кнопку;
4. импорт валидирует файл до записи, а ошибки говорят, что исправить;
5. `npm test` и `npm run build` проходят, а `dist` содержит актуальный статический сайт.
