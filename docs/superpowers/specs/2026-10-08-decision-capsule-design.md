# Decision Capsule — улучшение продукта

## Цель
Сделать локальный архив решений надёжным рабочим инструментом: пользователь быстро находит нужную запись, понимает её состояние, безопасно проходит путь от черновика до итога и может перенести архив без потери данных.

## Зафиксированные ограничения
- Данные остаются только в IndexedDB этого браузера.
- Нет аккаунтов, серверных запросов, аналитики, внешних шрифтов и сетевых напоминаний.
- Существующая дизайн-система сохраняет пергамент, бордо, зелёный и уголь; декоративные элементы подчиняются смыслу.
- Интерфейс на русском, формулировки короткие и операционные.
- Метаданные в `index.html` ограничиваются `charset`, `viewport` и `title`; theme-color и description удаляются.

## Пользовательские сценарии
1. В архиве пользователь видит одну сводку: всего записей, готовых к открытию, открытых и черновик. Фильтр, поиск и сортировка влияют на один и тот же список и показывают число найденных результатов.
2. Незавершённый черновик можно продолжить или удалить явным действием. Изменения сохраняются с debounce и последовательной очередью; в интерфейсе виден статус сохранения.
3. Пошаговая форма валидирует единый контракт: вопрос, контекст, минимум два непустых варианта, выбранный путь, уверенность 0–100 и дата не раньше даты устройства. Ноль процентов сохраняется как ноль.
4. Запечатывание записывает капсулу и очищает черновик одной транзакцией либо безопасно восстанавливает состояние после частичного сбоя.
5. До даты пересмотра исходные поля доступны только для чтения. Открытие возможно только в дату устройства или позже; открытая запись может иметь пустой итог, затем итог можно сохранять и редактировать.
6. Импорт сначала проверяет весь файл, затем атомарно добавляет новые ID и возвращает числа «добавлено/пропущено». Hash-превью не импортируется без явного действия; отмена закрывает и очищает hash.
7. Диалоги доступны с клавиатуры: фокус входит в диалог, остаётся внутри, Escape закрывает, после закрытия возвращается на вызвавшую кнопку.

## Доменная модель
`validateCapsule` становится единым источником инвариантов для модели, IndexedDB и импорта:
- `options` содержит не менее двух непустых строк;
- все timestamps — canonical ISO-строки, `sealedAt >= createdAt`;
- `openedAt` либо `null`, либо ISO после `sealedAt` и не раньше даты пересмотра по локальному календарю;
- `result` и `resultUpdatedAt` либо оба `null`, либо непустая строка и ISO; итог невозможен без `openedAt`;
- обновление прогресса разрешает только монотонный переход `sealed → opened` и изменение результата открытой записи.

Добавляются чистые помощники `statusCounts`, `daysUntilReview` и `normalizeDraft`, чтобы UI не дублировал правила.

## Хранилище
Репозиторий получает операции `sealCapsule(capsule, draft)` и `saveDraft(draft)` с последовательным выполнением внутри одной транзакции. `list()` валидирует записи перед возвратом; повреждённые записи изолируются в отчёте, а приложение показывает понятное сообщение и не падает целиком. Все ошибки транзакций приводят к abort.

## Интерфейс
- Архив: компактный заголовок, сводка, фильтры «Все/Запечатанные/Готовы/Открытые», строка поиска по вопросу, контексту, вариантам, выбранному пути и итогу, сортировка «дата пересмотра / новые / старые», карточки-строки с номером, состоянием, выдержкой и явной кнопкой.
- Создание: текущая структура шагов сохраняется, но тексты сокращаются; прогресс получает `role=progressbar` и текущий шаг; inline-стили заменяются классами.
- Детали: русская печать, явный блок состояния и даты, кнопка «Сохранить итог» при существующем значении, локальные сообщения об ошибках.
- Вспомогательные действия: экспорт JSON, импорт JSON, Markdown и share-hash остаются; добавляется продолжение/удаление черновика. Удаление записей не добавляется, чтобы не вводить необратимое действие без восстановления.

## Проверки
- Модель: строгие timestamps, противоречивые состояния, минимум два варианта, нулевая уверенность, переходы открытия/итога, дата и локальный календарь.
- Репозиторий: строгий `updateProgress`, атомарное seal+clear draft, rollback импорта, дубликаты, битые записи.
- UI: поиск по всем полям, filtered-ready, сохранение preset/option, resume/clear draft, hash duplicate report, dialog focus, mobile overflow.
- Перед завершением: `npm test`, `npm run build`, статический запуск и Playwright-проверка создания, reload, открытия, результата, импорта и мобильного layout.
